# RiskWatch 업무 명세

RiskWatch가 **무엇을 판정하고, 누가 무엇을 할 수 있는지** 정한 문서입니다. 코드와 테스트 명세(`docs/test-cases`)는 이 문서를 기준으로 합니다.
이 문서와 코드가 다르면 둘 중 하나를 고치고, 바꾼 이유를 PR에 적습니다.

- 작성: 2026-10-27 (1단계)
- 첫 기준 버전의 값은 HomeFin이 공식 페이지에서 확인한 값(2026-10-26 확인)입니다. 실제 심사에는 신용, 순자산, 면적 등 이 문서에 없는 기준도 있습니다(10장).

## 1. 범위

| 하는 것                                                                      | 하지 않는 것 (추후 또는 범위 밖)                  |
| ---------------------------------------------------------------------------- | ------------------------------------------------- |
| 정책대출 3개 상품의 심사 기준 판정 (적격 / 검토 필요 / 부적격) + 규칙별 근거 | 신용평가, 순자산·면적·규제지역 판정 (입력이 없음) |
| 심사 기준표를 DB에 버전으로 보관, 운영자가 새 버전을 만들어 변경             | 기준 변경 승인 절차(2인 결재 등), 예약 적용 취소  |
| 평가마다 입력·결과·기준 버전을 기록 (나중에 같은 판정을 다시 설명할 수 있게) | 주택보증 상품                                     |
| HomeFin(상담 단계 사전 판정)·FinFlow(신청 심사) 서버만 평가 API 사용         | 사용자 화면, AI 설명                              |

- **HomeFin 추천과의 관계:** HomeFin의 정책 추천은 상담용 안내이고(입력이 비어 있으면 "확인 필요"), RiskWatch는 **입력이 모두 있는 상태에서 기록으로 남는 판정**입니다. HomeFin 추천을 RiskWatch로 대체하는 것은 범위 밖입니다.

## 2. 호출 주체와 인증

| 주체         | 인증                                                            | 할 수 있는 것                              |
| ------------ | --------------------------------------------------------------- | ------------------------------------------ |
| HomeFin 서버 | 서비스 토큰 (`iss=homefin-mate`, 비밀키 `HOMEFIN_TOKEN_SECRET`) | 평가 요청                                  |
| FinFlow 서버 | 서비스 토큰 (`iss=finflow`, 비밀키 `FINFLOW_TOKEN_SECRET`)      | 평가 요청, 자기가 요청한 평가 조회         |
| 운영자       | 운영자 토큰 (`POST /api/auth/login`, 역할 ADMIN)                | 기준표 조회·새 버전 만들기, 평가 기록 조회 |

- 서비스 토큰은 FinFlow와 같은 방식입니다: HS256, `aud=riskwatch`, 유효 기간 5분 이하. **호출하는 서버마다 비밀키가 다릅니다.** 한 서버의 비밀키가 새어도 다른 서버인 척할 수 없고, 평가 기록에 어느 서버가 요청했는지(`sourceSystem`)를 토큰으로 정합니다(요청 본문 값을 믿지 않음).
- 운영자 계정·로그인·시도 제한은 FinFlow와 같습니다(BCrypt, `.env`로 첫 계정, 15분 5번 실패 시 429).
- 역할이 섞이면 403입니다.

## 3. 평가 입력 (`POST /api/evaluations`)

| 항목                                                         | 필수   | 규칙                                                                  |
| ------------------------------------------------------------ | ------ | --------------------------------------------------------------------- |
| `productCode`                                                | 예     | `DIDIMDOL` / `NEWBORN_DIDIMDOL` / `BOGEUMJARI`                        |
| `applicantRef`                                               | 예     | `homefin:` + 숫자                                                     |
| `sourceRef`                                                  | 아니요 | 요청한 쪽의 참조 (FinFlow 신청 번호, HomeFin 계산 기록 id), 64자 이하 |
| `requestedAmount`                                            | 예     | 원 단위 정수, 1 이상 10억 이하                                        |
| `termMonths`                                                 | 예     | 12 이상 600 이하                                                      |
| `housePrice`                                                 | 예     | 원 단위 정수, 1 이상                                                  |
| `householdAnnualIncome`                                      | 예     | 원 단위 정수, 0 이상 (부부합산)                                       |
| `dti`                                                        | 예     | 0 이상 9.9999 이하, 소수 넷째 자리                                    |
| `houseOwnership`                                             | 예     | `NONE`(무주택) / `RENT`(무주택·전월세) / `OWN`(주택 보유)             |
| `firstHome`, `newlywed`, `newbornWithin2Years`, `dualIncome` | 예     | true / false                                                          |
| `childCount`                                                 | 예     | 0 이상 20 이하 (미성년 자녀)                                          |
| `region`                                                     | 아니요 | 시·도 이름 (수도권 `서울`·`인천`·`경기`면 생애최초 LTV 우대 없음)     |

- 모든 판정 입력은 **필수**입니다. 값이 없으면 판정하지 않고 400입니다(HomeFin 추천처럼 "확인 필요"로 넘어가지 않음).

## 4. 심사 규칙

규칙마다 결과는 `PASS`(충족) / `WARN`(확인 필요) / `FAIL`(미충족)이고, 근거로 **규칙 코드, 이름, 기준값, 실제값, 결과, 설명**을 남깁니다.

| 규칙 코드           | 이름            | 디딤돌                                      | 신생아 특례                    | 보금자리론                                          |
| ------------------- | --------------- | ------------------------------------------- | ------------------------------ | --------------------------------------------------- |
| `PRODUCT_TARGET`    | 상품 대상       | 항상 PASS                                   | 2년 내 출산·입양이 아니면 FAIL | 항상 PASS                                           |
| `HOUSE_OWNERSHIP`   | 주택 보유       | 보유(OWN)면 FAIL                            | 보유면 FAIL                    | 보유면 WARN (1주택은 기존 주택 처분 조건 확인 필요) |
| `INCOME_LIMIT`      | 부부합산 연소득 | 기준 이하면 PASS                            | 기준 이하면 PASS               | 기준 이하면 PASS                                    |
| `HOUSE_PRICE_LIMIT` | 주택 가격       | 기준 이하면 PASS                            | 기준 이하면 PASS               | 기준 이하면 PASS                                    |
| `LOAN_LIMIT`        | 대출 금액       | min(상품 한도, 주택 가격 × LTV) 이하면 PASS | 같음                           | 같음                                                |
| `DTI_LIMIT`         | DTI             | 기준 이하면 PASS                            | 같음                           | 같음                                                |
| `TERM_LIMIT`        | 대출 기간       | 최대 기간 이하면 PASS                       | 같음                           | 같음                                                |

**판정:** FAIL이 하나라도 있으면 **부적격(`INELIGIBLE`)**, FAIL 없이 WARN이 있으면 **검토 필요(`REVIEW`)**, 모두 PASS면 **적격(`ELIGIBLE`)**.

**HomeFin 호환 값** (HomeFin이 이미 읽는 칸):

| 칸               | 값                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------- |
| `riskLevel`      | 적격 `LOW`, 검토 필요 `MEDIUM`, 부적격 `HIGH`                                                 |
| `riskScore`      | 0~100, `round(100 × (FAIL 수 + 0.5 × WARN 수) ÷ 규칙 수)` (점수는 판정을 바꾸지 않는 보조 값) |
| `recommendation` | 판정과 미충족·확인 필요 규칙 이름을 한국어 한 문장으로                                        |

## 5. 기준표 (DB, 버전)

기준값은 코드가 아니라 DB의 **기준 버전**에 있습니다. 기준 버전은 만든 뒤 바뀌지 않고, 바꾸려면 새 버전을 만듭니다.

| 기준 키                                             | 디딤돌     | 신생아 특례 | 보금자리론 |
| --------------------------------------------------- | ---------- | ----------- | ---------- |
| `INCOME_LIMIT` (기본)                               | 6,000만 원 | 1.3억 원    | 7,000만 원 |
| `INCOME_LIMIT_FIRST_HOME`                           | 7,000만 원 | —           | —          |
| `INCOME_LIMIT_NEWLYWED`                             | 8,500만 원 | —           | 8,500만 원 |
| `INCOME_LIMIT_ONE_CHILD`                            | —          | —           | 9,000만 원 |
| `INCOME_LIMIT_MULTI_CHILD` (자녀 2명 이상)          | 7,000만 원 | —           | 1억 원     |
| `INCOME_LIMIT_DUAL_INCOME`                          | —          | 2억 원      | —          |
| `HOUSE_PRICE_LIMIT` (기본)                          | 5억 원     | 9억 원      | 6억 원     |
| `HOUSE_PRICE_LIMIT_NEWLYWED_OR_MULTI_CHILD`         | 6억 원     | —           | —          |
| `PRODUCT_LOAN_LIMIT` (기본)                         | 2억 원     | 4억 원      | 3.6억 원   |
| `PRODUCT_LOAN_LIMIT_FIRST_HOME`                     | 2.4억 원   | —           | 4.2억 원   |
| `PRODUCT_LOAN_LIMIT_NEWLYWED_OR_MULTI_CHILD`        | 3.2억 원   | —           | —          |
| `PRODUCT_LOAN_LIMIT_MULTI_CHILD`                    | —          | —           | 4억 원     |
| `LTV` (기본)                                        | 70%        | 70%         | 70%        |
| `LTV_FIRST_HOME_NON_CAPITAL` (생애최초 + 수도권 밖) | 80%        | 80%         | —          |
| `DTI_LIMIT`                                         | 60%        | 60%         | 60%        |
| `MAX_TERM_MONTHS`                                   | 360        | 360         | 600        |

- **가구 조건이 여러 개 해당하면 가장 유리한(큰) 값**을 씁니다. 예: 디딤돌 신혼 + 생애최초면 소득 기준 8,500만 원. 자녀 기준은 1명 이상이면 `ONE_CHILD`, 2명 이상이면 `MULTI_CHILD`도 해당합니다.
- **LTV:** 지역을 비워 보내면 수도권일 수 있어서 생애최초 우대(80%)를 주지 않습니다(HomeFin과 같음). 주택 가격 × LTV는 원 단위 아래를 버립니다.
- **기준이 빠진 버전:** 그 상품에 필요한 기본 기준(`INCOME_LIMIT`, `HOUSE_PRICE_LIMIT`, `PRODUCT_LOAN_LIMIT`, `LTV`, `DTI_LIMIT`, `MAX_TERM_MONTHS`)이 없으면 다른 값으로 대신하지 않고 평가를 거부합니다(500, 설정 오류).
- **적용 시각:** 운영자가 만든 새 버전은 지정한 적용 시각(없으면 즉시)부터 쓰입니다. 평가할 때는 "적용 시각 ≤ 지금"인 버전 중 가장 최근 것을 씁니다.
- **변경 기록:** 버전마다 만든 운영자(토큰으로 정함), 사유(필수), 만든 시각, 이전 버전과 달라진 값이 남습니다. 기준 버전은 바꾸거나 지울 수 없습니다(API 없음).
- **새 버전 = 지금 적용 중인 버전 + 바꾼 값.** 적용 시각이 아직 오지 않은 버전(예약)이 있으면 새 버전을 만들 수 없습니다(409). 예약이 두 개 쌓이면 먼저 예약한 변경이 나중 버전에 복사되지 않아 사라질 수 있어서입니다.
- **값 검증:** 금액(`*_LIMIT` 중 DTI 제외)은 1 이상 정수, `LTV*`·`DTI_LIMIT`은 0 초과 1 이하, `MAX_TERM_MONTHS`는 12~600 정수. 상품에 없는 키, 같은 키 두 번, 지금 값과 같은 값, 과거 적용 시각은 400입니다. 버전 이름은 영문·숫자·`._-` 30자 이하입니다.
- **첫 버전** `2026-10-26`은 Flyway가 만듭니다(만든 사람 `system`, 사유 "공식 페이지 확인 값").

## 6. 평가 기록

- 평가마다 `evaluationId`(UUID), 요청 서버(`sourceSystem`: 토큰으로 정함), `sourceRef`, `applicantRef`, 상품, 판정, 점수, **기준 버전**, 규칙별 근거, 입력값, traceId, 시각을 남깁니다.
- 입력 중 연소득과 DTI는 암호화해서 저장합니다(AES-256-GCM, FinFlow와 같은 방식).
- 같은 입력을 다시 보내면 새 평가 기록이 생깁니다(평가는 상태를 바꾸지 않아서 멱등성 키를 쓰지 않음). 같은 입력 + 같은 기준 버전이면 판정은 항상 같습니다.

## 7. API

모든 응답은 공통 형식 `{status, message, data, traceId}`입니다. 시각은 시간대를 붙여 보냅니다(`…Z`).

| 메서드 | 경로                                                       | 주체                           | 내용                                                                                                                         | 단계 |
| ------ | ---------------------------------------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ---- |
| POST   | `/api/evaluations`                                         | SERVICE                        | 평가 → `{evaluationId, verdict, riskLevel, riskScore, recommendation, criteriaVersion, reasons[]}`                           | 4    |
| GET    | `/api/evaluations/{evaluationId}`                          | SERVICE(요청한 서버만) / ADMIN | 평가 기록 조회 (다른 서버의 평가는 404)                                                                                      | 4    |
| POST   | `/api/auth/login`                                          | 누구나                         | 운영자 로그인                                                                                                                | 3    |
| GET    | `/api/admin/criteria`                                      | ADMIN                          | 지금 적용 중인 기준 버전과 값                                                                                                | 3    |
| GET    | `/api/admin/criteria/versions`                             | ADMIN                          | 기준 버전 목록 (최신순, 만든 사람·사유·적용 시각)                                                                            | 3    |
| GET    | `/api/admin/criteria/versions/{version}`                   | ADMIN                          | 한 버전의 값 전체와 이전 버전 대비 바뀐 값                                                                                   | 3    |
| POST   | `/api/admin/criteria/versions`                             | ADMIN                          | 새 버전 만들기 `{version, effectiveFrom?, reason, changes[{productCode, key, value}]}` (바꾸지 않은 값은 지금 버전에서 복사) | 3    |
| GET    | `/api/admin/evaluations?productCode=&verdict=&page=&size=` | ADMIN                          | 평가 기록 목록                                                                                                               | 3    |

- `/actuator/health`만 인증 없이 공개합니다.

## 8. 연결 (4단계)

| 호출하는 쪽 | 언제                       | 바뀌는 것                                                                                                                                                 |
| ----------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HomeFin     | 통합 분석의 위험 평가 단계 | `RiskWatchClient`가 새 평가 API·서비스 토큰을 씀. 응답의 `riskLevel`·`riskScore`·`recommendation`은 지금 화면 그대로 쓰고, 판정·근거를 추가로 보여 줌     |
| FinFlow     | 운영자가 심사를 시작할 때  | RiskWatch 판정(평가 번호, 판정, 기준 버전)을 신청에 저장해 운영자 상세에서 보여 줌. RiskWatch가 응답하지 않으면 심사는 그대로 시작하고 "평가 불가"로 남김 |

- FinFlow 신청서에는 `houseOwnership`, `dualIncome`이 없어서 4단계에서 신청 입력에 추가합니다(FinFlow V5).
- 연결 실패 처리(타임아웃, 재시도, 서킷 브레이커)는 HomeFin이 이미 쓰는 방식을 따릅니다.

## 9. 데이터 모델

| 표                                     | 주요 칸                                                                                                                                                                                                                 | 단계 |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| `criteria_versions`                    | id, version(unique, 예: `2026-10-26`), effective_from, created_by, reason, created_at                                                                                                                                   | 2    |
| `criteria_values`                      | id, version_id(FK), product_code, criteria_key, criteria_value(DECIMAL(15,4)), (version_id+product_code+criteria_key unique)                                                                                            | 2    |
| `risk_evaluations`                     | id, evaluation_id(UUID unique), source_system, source_ref, applicant_ref, product_code, verdict, risk_level, risk_score, criteria_version_id(FK), reasons(JSON 문자열), 입력값(연소득·DTI 암호문), trace_id, created_at | 2    |
| `operators`, `operator_login_failures` | FinFlow와 같음                                                                                                                                                                                                          | 3    |

- enum 칸은 VARCHAR, 시각은 마이크로초까지(FinFlow #1, #4).

## 10. 판정하지 않는 기준

다음은 실제 심사에 있지만 입력이 없어 판정하지 않습니다. 평가 응답의 `notEvaluated` 목록에 이름만 남깁니다.

- 신용점수, 순자산, 전용면적, 규제지역 LTV·DTI 차감, 아파트 외 주택의 LTV(보금자리론 65%), 맞벌이일 때 부부 각자 소득 기준(신생아 특례)

## 11. 오류 응답

| 상태 | 언제                                                                                  |
| ---- | ------------------------------------------------------------------------------------- |
| 400  | 입력 형식, 기준 변경 값 형식(범위 밖, 없는 키·상품, 지금 값과 같음), 적용 시각이 과거 |
| 401  | 토큰 없음·만료·서명 오류, 발급자·대상 불일치, 로그인 실패                             |
| 403  | 역할이 맞지 않음                                                                      |
| 404  | 없는 평가·버전, 다른 서버가 요청한 평가                                               |
| 409  | 이미 있는 버전 이름, 예약된 버전이 있는데 새 버전                                     |
| 429  | 운영자 로그인 시도 제한                                                               |
| 500  | 예상 못 한 오류, 적용할 기준 버전이 없음 (일반 메시지만, 원인은 서버 로그)            |
