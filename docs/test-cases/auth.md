# 인증·인가 (TC-AUTH)

대상: 운영자 로그인, 운영자 토큰, 첫 운영자 계정(3단계), HomeFin·FinFlow 서비스 토큰과 역할(4단계) ([업무 명세 2장](../spec.md#2-호출-주체와-인증)).

- FinFlow 운영자 인증과 같은 방식이라 같은 관점으로 확인합니다: 정상(로그인), 예외(틀린 비밀번호), 경계(시도 제한 5번째·6번째), 보안(삭제된 운영자, 실패 기록의 이메일 원문, 운영자 API는 ADMIN만).
- 3단계에서 구현과 함께 자동화했습니다.
- **서비스 토큰(4단계):** 서버마다 비밀키가 다르므로, 한 서버의 비밀키로 다른 서버인 척하는 토큰(사칭)을 거부하는지와 평가 기록의 요청 서버가 토큰으로 정해지는지를 봅니다. FinFlow 서비스 토큰과 같은 관점(발급자·대상·만료·유효 기간 5분)도 봅니다.
- 4단계 행은 구현보다 먼저 쓰고 구현과 함께 자동화했습니다. TC-AUTH-203은 처음 구현(`Set.of`로 같은 값 확인)이 같은 값을 만나면 비밀키를 메시지에 넣은 다른 예외를 던진다는 것을 찾았습니다(커밋 전에 고침).
