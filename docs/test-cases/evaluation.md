# 기준표·평가 기록 (TC-EVAL)

대상: 평가 API(4단계), 기준 버전 선택(`CriteriaService`), 평가 기록(`EvaluationService`), Flyway 첫 기준 버전 ([업무 명세 3장·5장·6장·7장·9장](../spec.md#3-평가-입력-post-apievaluations))

- **관점:** 정상(평가 기록 저장, 기준 버전 선택), 예외(적용 중인 기준 버전 없음), 경계(적용 시각이 아직 오지 않은 버전), 보안(연소득·DTI 암호문)을 봅니다.
- 2xx는 서비스를 직접 불러 확인합니다(DB 포함, `@SpringBootTest`). 1xx(4단계)는 서비스 토큰으로 평가 API를 불러 확인합니다.
- **평가 API 관점:** 정상(평가·조회), 예외(필수 입력 없음, 형식 오류), 경계(입력 범위의 양쪽), 보안(다른 서버의 평가는 없는 평가와 구별되지 않음)을 봅니다. 판정 규칙 자체는 TC-RULE이 봅니다.
- 4단계 행(1xx)은 구현보다 먼저 쓰고 구현과 함께 자동화했습니다. TC-EVAL-104의 소수 입력은 구현 중에 추가했습니다: Jackson 기본값은 정수 칸의 `1.5`를 오류 없이 `1`로 읽습니다.
- 2단계에서 구현과 함께 자동화했습니다. 버전 선택 테스트는 만든 버전을 끝나면 지워서, 같은 DB를 쓰는 다른 테스트가 첫 버전으로 판정하게 합니다.
