# 알려진 문제

RiskWatch는 원본(거래·정산 데이터 기준 위험 점수)을 그대로 재현하지 않고, **정책대출 심사 규칙 엔진**으로 새로 설계합니다.
그래서 이 문서는 두 부분입니다.

- **원본에서 바꾼 것 (O1~):** 원본 코드에서 확인한 문제 중, 새로 만들 때 처음부터 다르게 만든 것
- **문제 목록 (#1~):** 이 저장소에서 새로 찾은 문제

**확인** 칸은 문제를 어떻게 확인했는지입니다 (코드 / 실행).

## 원본에서 바꾼 것

| 번호 | 원본                                                                                                         | 확인 | 이 저장소                                                                   | 테스트                   |
| ---- | ------------------------------------------------------------------------------------------------------------ | ---- | --------------------------------------------------------------------------- | ------------------------ |
| O1   | `application.yml`에 DB 비밀번호·JWT 비밀키·AES 키 기본값이 있어 `.env` 없이도 약한 값으로 실행됨             | 코드 | 비밀값은 기본값 없이 `.env`에서만 (없으면 compose·서버가 시작하지 않음)     | TC-BASE-301              |
| O2   | `ddl-auto: update` (엔티티를 바꾸면 DB가 몰래 바뀜)                                                          | 코드 | Flyway가 테이블을 만들고 Hibernate는 확인만(`validate`)                     | 테이블이 생기는 단계부터 |
| O3   | `X-Trace-Id` 헤더를 형식 확인 없이 로그(MDC)에 넣음, 없으면 접두사 없는 UUID                                 | 코드 | 형식(영문·숫자·`._-` 64자 이하) 확인, 없거나 틀리면 `rw-UUID`               | TC-BASE-101~103, 201     |
| O4   | `IllegalArgumentException`·`IllegalStateException`의 메시지를 그대로 응답 (내부 메시지가 나갈 수 있음)       | 코드 | 공개 오류는 `BusinessException`만, 나머지는 500 + 일반 메시지               | TC-ERR-202               |
| O5   | `RuntimeException`·`Exception` 전체를 500으로 처리 → 없는 주소(404)·허용하지 않는 메서드(405)도 500으로 바뀜 | 코드 | Spring 표준 예외는 원래 상태 코드 유지                                      | TC-BASE-106, TC-ERR-206  |
| O6   | 401/403 본문을 문자열로 직접 써서 traceId가 없음                                                             | 코드 | 401/403도 공통 오류 형식 + traceId (traceId 필터를 보안 필터보다 먼저 실행) | TC-BASE-104              |
| O7   | `open-in-view` 기본값(켜짐) → 요청 끝까지 DB 커넥션을 잡음 (HomeFin #71과 같은 문제)                         | 코드 | `open-in-view: false`                                                       | 평가 기록 단계에서       |
| O8   | 평가 API(`/risk/evaluate`)가 `permitAll` → 누구나 인증 없이 심사 평가를 부를 수 있음 (HomeFin #73)           | 코드 | 평가 API는 서비스 토큰(HomeFin·FinFlow)만, 기준 변경은 운영자만             | 평가 API 단계에서        |

FinFlow에서 찾은 문제(테스트 시간대 #2, 시각 정밀도 #4, MySQL enum 매핑 #1)는 처음부터 반영합니다.
